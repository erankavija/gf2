permanent_sampling_feas — feasibility measurements for the permanent-zero-fraction
campaign (JIT issue b488f02c).

SUBCOMMANDS
  equivalence  Compare per-matrix permanent values across every backend on shared
               inputs. Exits non-zero on any mismatch. Run this before `grid`;
               a throughput number from a disagreeing backend is not evidence.
                 --out PATH        output CSV (default equivalence.csv)
                 --matrices N      matrices per (q, n) cell (default 512)

  grid         Time the composite campaign hot path over q in {3,5,7} and
               n in {12,16,20,24,28} on every backend. Requires an idle host.
                 --out PATH        output CSV (default throughput.csv)
                 --only CLAUSES    comma-separated q=,n=,backend=,batch_size=
                                   filter; clauses combine with AND
                 --execution-id N  reserve a disjoint stream-index block for
                                   this fresh process (default 0)
                 --skip-machine-warmup
                                   skip the 90 s whole-machine warmup when a
                                   caller holds the host lock across executions
                 --resume          append to an existing --out CSV, skipping the
                                   cells it already records. Sound because the
                                   cell schedule and per-cell seed streams are a
                                   pure function of root seed and execution id.

  sustained    Stream the composite hot path for a fixed window per backend, to
               confirm the short-cell projections survive thermal steady state.
                 --out PATH        output CSV (default sustained.csv)
                 --seconds S       window per run (default 300)

  gray-update  Time a dependency-chained packed Gray add/subtract on one
               accumulator for every registry-derived candidate.  CPU duration
               excludes sampling, packing, policy-loop, and output overhead;
               HIP spans are kernel-only device-event spans, excluding
               allocation, transfer, submission, and host-loop overhead.
                 --out PATH        output CSV (default gray-update.csv)
                 --q Q             measure one field order (default all 3,5,7)
                 --n N             active accumulator lanes (default 12)
                 --steps N         chained add/subtracts per repetition
                                   (default 1000001; must be nonzero)
               Output reports `net_per_operation_s` as `(update - compiler-barrier
               baseline) / (steps * reps)` across the timed repetitions; a nonpositive
               subtraction is explicit and has no reported net duration.
               Native representations are explicit: F_3 CPU/HIP uses Bipedal3
               two-plane packing; F_5/F_7 CPU uses packed arithmetic, while
               F_5/F_7 HIP currently measures their shipped byte controls.

  horizontal-product
               Time the branch-aware horizontal row product for every
               registry-derived candidate. Zero-product and nonzero-product
               samples are counted unconditioned; they are timed separately
               only where the circuit exposes an actual branch. GPU timing is
               device-event-only, never a host-clock substitute.
                 --out PATH        output CSV (default horizontal-product.csv)
                 --q Q             measure one field order (default all 3,5,7)
                 --n N             active row-sum lanes (default 12; 1..=63)
                 --samples N       independent unconditioned row-sum vectors
                                   per repetition (default 4096; must be nonzero)
               `zero_fast_observed_numerator` and
               `zero_fast_observed_denominator` name the zero-product
               frequency's exact timed-sample fraction; the analogous
               `nonzero_slow_*` columns name its complement. Their expected
               values are `1 - ((q-1)/q)^n` and `((q-1)/q)^n`.
               Each branch's net duration uses only its actual timed-operation
               denominator: `(product event spans - same-geometry barrier
               spans) / branch operations`. A branch with no timed observation
               or a nonpositive subtraction is explicitly unavailable, not zero.

  envelope     Derive required sample counts and wall-clock from a throughput CSV.
                 --throughput PATH input CSV from `grid` (required)
                 --out PATH        output CSV (default envelope.csv)
                 --budget-hours H  campaign budget per cell (default 12)

  zerofrac     Pool the zero counts the timing runs produced into a preliminary
               Pr[per = 0] per (q, n) with a 95 % Wilson interval. Sample sizes
               follow the timing protocol, so these are a by-product rather than
               a campaign result.
                 --throughput PATH throughput CSV to pool
                 --sustained PATH  sustained CSV to pool
                 --out PATH        output CSV (default zero-fraction.csv)

The GPU backend needs `--features hip`; without it its cells are recorded as
unsupported rather than skipped.

GRID TIMING COLUMNS
  `total_s`, `gen_s`, `eval_s`, `reduce_s`, and `store_s` are host wall-clock
  totals over the timed repetitions. For an instrumented GPU/HIP cell,
  `kernel_device_s` is instead the device-event kernel-only total: it excludes
  allocation, H2D, D2H, host serialisation, and submission overhead.

  `h2d_device_s` and `d2h_device_s` are device-event transfer totals.
  `host_submission_s` is the host-clock total around the submission wrapper;
  `device_submission_to_kernel_s` is the separate device-event total between
  the pre-submission marker and kernel start. They must not be combined by
  subtracting one clock from the other.

  The five per-phase fields are empty for CPU, unsupported, and unexecuted
  cells (or any path that lacks the instrumented boundary). `phase_timing_note`
  states why; a missing phase is never encoded as zero or substituted with a
  wall-clock duration. If event instrumentation is unavailable but the
  synchronous `gpu_hip` evaluator succeeds, its same-backend values still
  contribute to the cell while the phase fields remain empty and the note names
  the failed timing boundary.
