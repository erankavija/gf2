Motivation · 3 / 18

Why a new simulation pipeline

  • v1 (gf2_coding::simulation) is a monolithic runner: no stage graph, no GPU path, per-SNR-only parallelism
  • Research-grade goals: reproducibility (byte-identical results across worker counts and across CPU/GPU), composability (novel chains without forking the harness), throughput
  • Standards as foundation: DVB-T2 (ETSI EN 302 755) and 5G NR LDPC (3GPP TS 38.212) as the two production presets
Design SSOT: dev/active/ec530af9-pipeline-design.md — 15 locked architecture decisions, reviewed before any code.

Two ways to build a pipeline

  • Typestate presets — compile-time-checked builder order; wrong order is a compile error (trybuild-verified)
  • Graph API (Chain) — add / connect / build with topo-sort and edge type re-validation, for novel research chains

Determinism · 7 / 18

How byte-identity survives parallelism

  • One ChaCha20 stream; position selected by word-offset strides: SNR 1<<56, worker 1<<40, frame 1<<20
  • Every frame keyed on its global index — the outcome is a pure function of the frame number, not of which worker ran it
  • Counters reduced in worker order (SSOT order, mandatory)
  • Stride headroom regression-guarded: worst measured frame draw is 260,208 words (r1/2 QPSK binds — most symbols, most noise), ~4x margin
Worst case found empirically, then pinned by a fast-tier test that enumerates every supported modulation.

Throughput · 10 / 18

Hybrid executor

  • Rayon workers prepare batch N+1 on CPU while HIP streams decode batch N — double-buffered, per-worker stream ownership (pool.get(i))
  • 123.03 fps hybrid vs 21.44 CPU-24 — 5.74x; overlap attestation: 100% of eligible intervals genuinely overlapped
  • DAG topology executor: Kahn waves, fan-in/out refcounting, per-stage spans
  • Failure policy: GPU OOM → CPU fallback (strict mode promotes to fatal); stateful-scratch fallbacks refused, never silently re-seeded
  • Checkpointed sweeps abort resumably on GPU faults — determinism over availability
Robustness · 11 / 18

Checkpoint / resume

  • Heartbeat checkpoints within an SNR point: per-worker RNG word positions + cumulative counters, atomic write + fsync
  • Kill-during-fsync proven by a real subprocess kill test
  • SIGINT flushes, exits non-zero; --resume continues byte-identically vs an uninterrupted run
  • Hybrid path: GPU drain-for-checkpoint stops at batch-aligned points
One shared double-buffer core (hybrid_core.rs) drives both the scheduler and the checkpointed sweep — the only divergences are failure semantics and stop-after-batch, expressed as monomorphized hooks.

Applications · 13 / 18

5G NR LDPC (Phase E)

  • BG1 (46×68) + BG2 (42×52), per-i_LS shift tables for all 8 lifting sets — validated bit-exact vs Sionna reference CSVs
  • 3GPP rate matching via LLR initialization; §5.4.2.2 interleaver validated against the spec text + Sionna codegen
  • Typestate preset: BG1 × {1/3, 1/2, 2/3, 5/6}; BG2 × {1/3, 1/2, 2/3} (BG2 capped at R ≤ 0.67); all 51 lifting sizes
  • Driven per-batch by TopologyExecutor::run
The per-i_LS table trap (a single table costs ~2 dB BLER) was a known failure mode — designed out from day one.
