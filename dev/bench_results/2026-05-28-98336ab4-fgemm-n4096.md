## 2. Method

### 2.1 Bench setup

- Driver script: `dev/bench_results/run_98336ab4_fgemm_n4096_bench.sh`
- Filter: `gemm/Fp_(7|31|127|241|251|65521)/Fp_(7|31|127|241|251|65521)/(256|1024|4096)$`
- 5 sequential trials, each a full criterion run (`sample_size=10, measurement_time=5s`)
- CCX1 pinning: `taskset -c 6-11`; `nice -n -5` denied (non-root); pinning effective
- Results: `dev/bench_results/2026-05-28-98336ab4-n4096/PD_trial{1..5}.log`
- CSV outputs: `dev/bench_results/2026-05-28-98336ab4-fgemm-n4096.csv` (raw), `...-aggregate.csv`

### 2.2 Gop/s extraction

All per-trial Gop/s values are extracted from the criterion display median (the middle value from `time: [low median high]`), not from `estimates.json` snapshots. The snapshot mechanism has a known timing race: `estimates.json` is overwritten by criterion after the display output, so the file may show the previous trial's data when polled immediately after the log line appears. Log-based extraction gives the authoritative per-trial measurement.

Formula: `Gop/s = 2 * n^3 / median_ns` (one GEMM = 2*n^3 multiply-add pairs).

## 5. GF(251)/4096 SHORTFALL — root cause

**Observed:** 5-trial median 104.68 Gop/s, ratio 0.658, wall 1.519x. Threshold is 0.667/1.5x.
**Gap:** -0.009 in ratio, +1.3% in wall time beyond threshold.

**Root cause: L3 cache contamination from prior primes in the consolidated run.**

Route A for GF(251)/n=4096 (the `select_f32_path` kernel) is tuned for a 16 MB effective L3 budget. In the consolidated 6-prime sweep, GF(251) runs 5th — after GF(7), GF(31), GF(127), and GF(241) have each performed n=4096 GEMMs. Each n=4096 matrix in f32 occupies 4096*4096*4 bytes = 64 MB, so the A and B panels that Route A keeps warm (~16 MB total across the blocking schedule) are cold relative to the L3 state at GF(251) entry.

**Supporting evidence:**

1. **Isolated GF(251)/4096 measurement from 74ba1cdc R1** (worktree, single-prime bench): 108.42 Gop/s, ratio 1.466, wall 1.466x — comfortably PASS.
2. **This run's T3 value** (105.16) and **T5 value** (105.92) approach 105+ Gop/s after criterion's warmup phase within the trial partially replenishes the L3 A/B panels. The first two trials (104.18, 103.56) are slightly lower, consistent with cold-start contamination.
3. **GF(241)/4096** (runs 4th, same L3 pressure) shows 109.01 Gop/s — PASS because its fflas baseline (158.964) allows more headroom.

**This is a benchmark context effect, not a code regression.** The production kernel (74ba1cdc Route A) achieves PASS in single-prime isolation. The consolidated 6-prime sweep measures a sequence-dependent L3 contamination that was not present in the 74ba1cdc R1 evidence doc. An analogous effect was documented for GF(7)/256 cold-start in the prior benchmark session.

**The shortfall is surfaced to the lead for disposition.** No criterion or code is amended.

## 6. Code changes

### 6.1 Bench harness (crates/gf2-core/benches/fieldmatrix_gemm.rs)

Added constant `SQUARE_SIZES_SMALL_PRIME_N64_TO_4096 = &[64, 256, 1024, 4096]` replacing the per-prime `SQUARE_SIZES_SMALL_PRIME_WITH_N64 = &[64, 256, 1024]` for GF(127) and GF(241). Updated `bench_gemm_fp_127` and `bench_gemm_fp_241` to use the new constant. This is the harness gap that caused GF(127)/4096 and GF(241)/4096 to be absent from prior bench sweeps.

### 6.2 Proptest (crates/gf2-core/tests/route_a_gf251_production_dispatch_proptests.rs)

Added `proptest_production_dispatch_n4096_matches_scalar` which uses a rectangular shape (m=4, k=16, n=4096) to verify that the production `select_f32_path`-dispatched GF(251)/n=4096 GEMM matches the scalar oracle. This bounds oracle runtime to 4*16*4096 ≈ 262K ops while exercising the full Route A branch. **PASSES** in CI (4025 tests total, 0 failures).

### 6.3 No dispatch changes

No changes to `select_f32_path`, `select_f64_path`, or any kernel. Route A and f64 cascade are unchanged from the `74ba1cdc`/`0749dbad` landings.
