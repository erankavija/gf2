Key Algorithmic Wins

  • Wiedemann + extension-field embedding (minpoly / charpoly)
    Low-cardinality fields (e.g. GF(7)) trigger Wiedemann over a quadratic extension, reducing scalar-field ops by O(p²). Achieved 0.17–0.23× vs fflas-ffpack at n=256 on GF(7).
  • In-place trtrm invert (GF(2^31-1) invert/deficient)
    Reuses PLE triangular factors in-place, eliminating copy overhead. All deficient-regime invert cells PASS; n=64 uniform 0.67×.
  • PLE-driven solve / echelon (GF(2^31-1))
    TRI_BASE_THRESHOLD=8 tuning: pluq all sizes PASS (0.55–1.07×); solve all sizes PASS (0.24–0.60×); echelon n∈{256,1024} uniform PASS.
  • Panelized fgemm kernel (GF(2^m))
    Column-panel tiling with VPCLMULQDQ. GF(2^32) matmul: 0.15–0.18× vs NTL. GF(2^16) n=64,256 PASS [hard] (148× and 35.6× faster than M4RIE).
  • M4RM production kernel + blocked RREF (GF(2))
    echelon: all 6 cells PASS (1.03–1.39×); matmul PASS at n≥1024 (1.10–1.12×).
The five major algorithmic investments that drove closure across the families. The Wiedemann extension-field trick is the most novel: for small-cardinality fields the Krylov projection over GF(p^2) avoids repeated field-element inversions in the base field. The in-place trtrm reuse is a classical trick but its implementation here eliminated an allocation bottleneck. PLE-driven echelon inherits the PLE permutation directly rather than recomputing. Panelized CLMUL with 4-row panels exploits register reuse across B-matrix rows.

The sparse story has two distinct sub-stories. spmv, sparse-matmul, and sparse-times-dense are all clean wins: gf2 matches or beats fflas and LinBox across all fields. The GF(2) sparse-times-dense result is dramatic: 412x faster in wall time due to bitwise SIMD vs LinBox's scalar loop (unit-mismatch documented in target matrix §5.10). sparse-elim is a uniformly open gap. LinBox's GaussDomain::NoReordering implements Markowitz-degree pivot selection which keeps fill-in dramatically lower than gf2's simple column-sweep. This is a non-trivial algorithmic change, not a constant-factor optimization. Tracked in 5ce13bae (filed 2026-05-08; correctly-scoped replacement for the original 4c0d0202 misattribution). GF(2^8) and GF(2^16) sparse-elim are self-canonical (PASS by definition) because no external library exposes sparse RREF on GF(2^m) extension fields.

All 7 amendments are [aspirational] criterion changes: they were written optimistically before empirical data existed and are now grounded in measured ratios and architectural causes. A1 is the only amendment where the cells are explicitly recorded as FAIL for this epic's contract; the others count as PASS-equivalent for scorecard purposes. A7 is architecturally fundamental: fflas uses OpenBLAS sgemm to convert small-prime field arithmetic into floating-point, achieving ~130 Gops/s. A pure integer SIMD kernel is structurally bounded below this ceiling. Closing A7 requires either a float-modular implementation or a different algorithmic approach.

Future Research Bucket

Four open follow-up issues from the epic closure:

IssueTitleConnection to closure gaps
52cce970 Bespoke small-prime AVX2 kernel Closes A1 cells: charpoly × GF(251)/n=256 (3.18×) + minpoly × GF(251)/n=64 (4.14×). Register-scheduled hand-written kernels in gf2-kernels-simd.
27bb2f75 Optimize small-n GEMM dispatch (n ≤ 128) Closes A5 (GF(31)/n=64 fgemm) + A6 (GF(7)/n=64 fgemm) + A7 n=64 cell. Per-call SIMD setup overhead dominates at n=64; needs lightweight dispatch or pre-amortised layout.
615db3b9 Byte-prime / float-modular gap exploration Closes A2 (GF(2^8) Newton-John algorithm) + A7 (GF(251) vs OpenBLAS sgemm ceiling). Architectural: either a float-modular kernel or a Newton-John / Gray-code table algorithm.
5ce13bae Sparse RREF priority-queue pivoting Closes sparse-elim algorithmic gap (10 cells, all 2.1–2.6× of LinBox). LinBox uses Markowitz-degree pivoting; gf2 uses column-sweep. Requires priority-queue data structure.
These four issues represent the research agenda that emerges from the epic closure. 52cce970 and 27bb2f75 are relatively well-scoped engineering tasks: writing AVX2 kernels and reducing dispatch overhead. 615db3b9 is a design-space exploration: the fundamental question is whether gf2 should implement a float-modular BLAS cascade for small primes (cardinality <= 251) similar to fflas's Modular path. 615db3b9 is the most algorithmically interesting: Markowitz pivoting for sparse RREF reduces fill-in asymptotically and the 2x gap vs LinBox is consistent across all fields, suggesting an algorithmic rather than implementation-level gap.
