# 40195c09 — `gemm_axpy_into_view` lift evidence

Issue `40195c09` — Phase 6 prereq under epic
`026fc832`. Lifts `gemm_axpy_into_view` to dispatch the whole-GEMM
small-prime AVX2 fast path (`fp_small_try_gemm_classical`, `P ≤ 251`)
and the pre-packed medium-prime u16 fast path
(`try_fp_simd_dot_packed_u16`, `252 < P < 65536`), bringing `trsm_lower`
/ `trsm_upper` and the existing PLE Schur-update path under the same
panelised dispatch the standalone `gemm()` already used.

Trial-level Criterion JSON / log files live alongside this doc under
`dev/bench_results/2026-05-26-40195c09-gemm-axpy-lift/` — one
`*.log` per (trial, size, pre|post) cell, captured via
`taskset -c 6-11 nice -n -5 target/release/deps/triangular-*`
(CCX1 pinning, matching the `41096af5` post-wire-in protocol).

## Strategy

**Strategy 1 (scratch-buffer + add-into-view)** — chosen from the
issue dispatch's two options.

`gemm_axpy_into_view` computes `out ← α · A · B + β · out` cell by
cell, reading the old `out[i, j]` before writing the new value (the
trsm/trmm aliasing contract). The lifted dispatch:

1. Transpose `B` once (existing one-shot allocation).
2. If `F::has_simd_gemm_classical()` is `true` AND
   `m * k * n ≥ 16³ = 4096` (threshold gate, see below), pack `A`
   into a contiguous `Vec<F>` (sub-views are row-strided so this is
   a `O(m·k)` copy), allocate an `m × n` `Vec<F>` scratch, call
   `F::try_simd_gemm_classical(&a_flat, b_t.data, m, k, n, &mut
   scratch)` once, and fold
   `out[i, j] ← α · scratch[i, j] + β · out[i, j]` row by row.
3. Otherwise, if `F::try_pack_fp_medium_u16` accepts the field AND
   `m * k * n ≥ 4096`, pre-pack `A` (via the contiguous copy) and
   `B^T` into u16 buffers, then run the per-cell
   `try_fp_simd_dot_packed_u16` kernel — mirroring the
   medium-prime block in `gemm()`.
4. Otherwise, fall back to the original per-cell
   `dot_product_slices` loop (Mersenne-31, GF(2^m), and every
   non-`Fp<P>` field, plus tiny shapes below the threshold).

`Fp<P>` overrides `has_simd_gemm_classical()` via the new
`fp_small_gemm_classical_available::<P>()` probe (returns `true`
exactly when `P ∈ [3, 251]` and any of the three small-prime
kernels — Candidate C, route A, route C — is detected at runtime).
Every other field keeps the default `false` so the new code path
is statically dead on Mersenne-31, GF(2^m), `QuadraticExt`, etc.

### Threshold derivation

The recursive `trsm_*` calls `gemm_axpy_into_view` at every
recursion level. At `TRI_BASE_THRESHOLD = 8` the leaves are
scalar back-substitution; the level above invokes
`gemm_axpy_into_view` at `m, k, n ≈ TRI_BASE_THRESHOLD = 8`.
At these tiny shapes the contiguous-`A` copy plus the `m × n`
scratch alloc dominate the kernel's inner work, and the existing
per-cell `fp_small_try_dot_vec` (which already packs bytes and
runs an AVX2 batch dot per cell) is faster. Empirical sweep
verified the threshold at `m · k · n = 16³ = 4096`: trsm
recursion `levels ≥ ceil(log2(n / 8))` skip the fast path, the
top `O(log n − 4)` levels take it. With n=256 the top three
recursion levels take the lift; at n=1024 the top five.

## Non-regression sweep

Existing `41096af5` PASS cells (`Fp<MERSENNE_31>`, `Gf2mWide<1,
AES>` — every non-`Fp<P>` cell where the default
`has_simd_gemm_classical() → false` keeps the lift statically dead):

| Bench | PRE median (ms) | POST median (ms) | Δ% |
|-------|-----------------|------------------|-----|
| `trsm_upper/Fp_M31/256`     | 6.631 | 6.638 | +0.1% |
| `trsm_upper/Gf2m8/256`      | 492.7 | 474.4 | −3.7% |
| `trsm_lower/Fp_M31/256`     | 6.550 | 6.334 | −3.3% |
| `trsm_lower/Gf2m8/256`      | 479.3 | 470.8 | −1.8% |

No regression on any non-Fp cell (every Δ within ±5%, the
criterion #2 bound). Fp_M31 and Gf2m8 either improve marginally
(noise-level) or are unchanged — exactly the expected behaviour
because the new code paths are statically `false`-gated for
these fields.

### PLE Schur-update non-regression (R1 addition — SC#2)

Measured via `crates/gf2-core/examples/ple_timing.rs` (20 iters,
median; 5 independent trials; `taskset -c 6-11`). Pre-lift binary
built with `GEMM_AXPY_FAST_PATH_THRESHOLD = usize::MAX` (fast path
disabled); post-lift binary with `16 * 16 * 16` (production value).

At n=256 the recursive PLE decomposes into Schur-complement updates
whose `m * k * n` product is mostly below the 4096-threshold, so the
lift is largely inactive here — the expected result is near-zero delta,
confirming no regression was introduced.

|-------|-----------------|------------------|-----|---------|
| `ple/Fp_7/256`     | 4.639 | 4.651 | +0.3% | no regression |
| `ple/Fp_251/256`   | 4.815 | 4.815 | 0.0%  | no regression |
| `ple/Fp_65521/256` | 4.865 | 4.857 | −0.2% | no regression |

All three cells within ±1% — well inside the ±5% bound of SC#2.

## Test coverage

The lift adds five new tests (`crates/gf2-core/src/field/matrix.rs`):

1. `test_gemm_axpy_into_view_fp251_small_prime_path` — explicit
   `Fp<251>` × scalar-oracle equality at the three n ∈ {16, 64, 256}
   cells mandated by criterion 7. Verifies the lifted path
   bit-exactly against an independent scalar `α · Σ a · b + β · c`
   walker.
2. `test_gemm_axpy_into_view_small_prime_boundary_lengths` —
   boundary-length sweep at lengths {0, 1, 15, 16, 17, 63, 64, 65}
   for `Fp<P>` with `P ∈ {7, 31, 127, 241, 251}`. Exercises the
   `α = −1, β = 1` (trsm submul), `(1, 1)` (addmul), `(0, 1)`,
   `(1, 0)`, and a random `(3, 5)` cell so the aliasing
   read-before-write path is hit at every prime.
3. `test_gemm_axpy_into_view_fp65521_medium_prime_boundary_lengths`
   — same sweep at `Fp<65521>` (largest medium-prime fit). Forces
   the lifted u16-pack medium-prime branch.
4. `test_gemm_axpy_into_view_fp251_strided_a` — verifies the
   `A` contiguity copy by feeding a `strided` MatView (col_offset
   16, cols 32 < parent_cols 128) and comparing against the
   manually-copied dense oracle. Guards against accidental leak
   of non-A parent columns into the kernel.
5. `prop_gemm_axpy_into_view_fp251_matches_oracle` — proptest at
   `Fp<251>` over random `(α, β, n_idx, seed)` covering the
   boundary lengths. 256 random seeds × 7 sizes × random `α, β`.

**R1 additions (SC#3 six-prime proptest sweep):**

6. `prop_gemm_axpy_into_view_fp7_matches_oracle` — same proptest
   pattern for `Fp<7>`.
7. `prop_gemm_axpy_into_view_fp31_matches_oracle` — same for `Fp<31>`.
8. `prop_gemm_axpy_into_view_fp127_matches_oracle` — same for `Fp<127>`.
9. `prop_gemm_axpy_into_view_fp241_matches_oracle` — same for `Fp<241>`.
10. `prop_gemm_axpy_into_view_fp65521_matches_oracle` — same for
    `Fp<65521>` (medium-prime path, not small-prime AVX2).

Also added: `crates/gf2-core/examples/ple_timing.rs` — hand-rolled
timing harness (not a test) for the PLE Schur-update non-regression
measurement above.

All ten tests pass under the standard fast test tier
(`cargo nextest run --workspace --all-features --release
--profile ci`).

## Hardware / protocol

- Host: 24-physical-core Zen4 (`AMD Ryzen 9 7900X`) — CCX1
  cores 6–11.
- `taskset -c 6-11 nice -n -5 target/release/deps/triangular-*`
  (matching the `41096af5` post-wire-in protocol). The `nice -n
  -5` may report "Permission denied" on non-root invocations;
  the taskset pinning still applies and is what dominates the
  variance reduction.
- Criterion: 5 sample, 1 s warmup, 3 s measurement at n ∈ {64,
  256} and 2 s warmup, 4 s measurement at n=1024.
- 5 independent trials per cell; the table rows show the
  `time: [low MEDIAN high]` middle column from each trial.
