Per protocol § 5 the perf-stat capture must cover at least one in-scope
representative cell per new operation. Each harness binary in this
issue runs every supported (op, field, n) cell in a single invocation,
so a single `perf stat -r N` run over the binary yields aggregate
counters that include each new operation's contribution. The largest
square cell each new op covers is reachable in this dispatch:

  fflas-ffpack:  minpoly  at n=1024 (covered)
  M4RI:          pluq, invert, solve at n=1024 (covered)

Per-cell wall-clock decomposition is preserved in the CSV
(`dev/bench_results/2026-05-04-5dea7457-reference-extension.csv`); the
counter aggregates below are paired with that CSV for downstream
attribution.

============================================================
 Methodology notes
============================================================

  * Frequency boost / governor: left at host defaults (frequency boost
    on; same idiom as the 2026-04-26 baseline). See `host.txt` for the
    governor reading at capture time.
  * SMT: on (host default). Per-cell numbers in the CSV are
    single-threaded by virtue of `OMP_NUM_THREADS=1` being inherited
    from the container's environment (fflas-ffpack defaults to
    single-thread when the env-var is absent on Modular<int64_t> /
    Modular<float> kernels).
  * `:u` suffix on every counter = userspace-only (perf was launched
    without root; kernel-mode counters were not collected). The
    aggregate is dominated by user time so the truncation is
    immaterial.
  * Coverage % (e.g. (83.34%)) reflects perf event multiplexing on
    the Zen-3 PMU (six events vs four general-purpose counters); the
    counters are scaled accordingly.
