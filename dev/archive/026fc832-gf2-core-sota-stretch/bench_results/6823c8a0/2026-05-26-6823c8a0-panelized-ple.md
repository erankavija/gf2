## Methodology

- **Trials per cell:** 3 warmup + 5 measured invocations of `FieldMatrix::ple()`.
  Median of the 5 trial wall times reported.
- **Pinning:** `flock -x /tmp/gf2-ccx1.lock taskset -c 6-11 nice -n -5` via
  `dev/benchmarks/ccx1-bench-flock.sh`. (`nice -n -5` denied for non-root;
  the wrapper script proceeded under default niceness 0.)
- **Build:** `cargo test -p gf2-core --release --all-features --lib`.
  The test harness `test_ple_panelized_wall_time_full_sweep` (ignored)
  drives the sweep; output is emitted as CSV lines to stderr between
  the markers `--- panelized-ple-sweep BEGIN ---` and `--- panelized-ple-sweep END ---`.
- **Matrix construction:** Deterministic per-cell seed:
  `seed = P * 0x9E3779B9 + n (+ 0x1234 for deficient)`. Uniform regime
  uses `random_fp::<P>(n, n, seed)`; deficient regime constructs
  `F · G` with rank `n/2` via `random_fp::<P>(n, rank, seed) ·
  random_fp::<P>(rank, n, seed + 0xCAFE)`.
- **fflas-ffpack reference:** values from
  `dev/bench_results/2026-05-08-dece4e73-sota-aggregate-reference.csv`
  rows tagged `fflas-ffpack,pluq,...` (`3b762764` capture, 2026-05-04).
  No new fflas measurement was taken in this run.
- **Ratio definition:** `Ratio = gf2 wall / fflas wall` (lower is better).
  PASS threshold: Ratio ≤ 1.5×.

## SHORTFALL root cause analysis

### GF(251) (rows 10-13 + new n=1024)

GF(251) pluq inherits the float-modular GEMM gap (fflas BLAS cascade;
A7 amended in scorecard). fflas-ffpack runs pluq at GF(251)/n=256 in
~568 µs by cascading sgemm-based pluq through float modular reduction,
achieving roughly 30 Gop/s for the dense factor. The current panelized
PLE kernel runs at ~8 Gop/s — limited by:

1. **Outer column-by-column pivot loop.** Each pivot requires a scalar
   pivot search + scale + Schur update; the algorithm itself does not
   block.
2. **Pivot-row buffer copy per pivot.** 256 bytes × 256 pivots = 65 KB
   of stack-buffer copies.
3. **Per-row scalar multiplier computation.** The pivot inverse
   lookup is L1-fast but still O(1) scalar mod-mul per row per pivot.

A 1.5× target ratio (≤ 0.85 ms for GF(251)/n=256/uniform) would
require ~3.6× more speedup over what the row-major axpy kernel
delivers; closing this gap is structurally a "recursive panel × panel
PLUQ blocking" change, not a small tweak on the base kernel. The same
root cause applies at n=1024 (ratio 2.89×) and n=64 (2.16×) — the
smaller n cell has fewer pivots but is dominated by fixed pivot-loop
overhead rather than the Schur update.

### GF(65521) (rows 14-17 + new n=1024)

GF(65521) takes the scalar `ple_base_direct` base case (the panel
kernel is byte-lane only, `P <= 251`) and inherits the medium-prime
Schur-update GEMM speedup automatically via `gemm_axpy_into_view`'s
74ba1cdc R1 / 40195c09 lift. The remaining gap (2.04×-3.44×) reflects
the gap between:

- gf2's `fp_medium` u16-lane Schur GEMM kernel (panelized for u16
  storage, no special pluq blocking)
- fflas-ffpack's pluq × GF(65521) implementation, which is also
  panelized via Modular<int16> with sgemm cascade

The medium-prime path inheritance does close the n=256/1024 ratios
from 7.34×/8.58× to 2.23×/2.28×, but does not close the n=64 cells
where the GEMM panel-pack overhead dominates. The cells were
classified FAIL pre-change; they remain FAIL but with substantially
smaller gaps.

## Non-regression sweep (Fp<MERSENNE_31>)

The `PLE_PANEL_COLS` default value is `Self::PLE_BASE_COLS` (= 1) for
all fields except `Fp<P>` with `P <= 251`. `Fp<MERSENNE_31>` therefore
takes the unchanged recursive trsm+gemm path; allocation-budget tests
`test_ple_allocation_budget_*` continue to pin the same integer
allocation counts. Verified in workspace test suite (3888 tests pass;
see `git log -1 88519bb2`).

## Code-change summary

- New trait constants: `FiniteField::PLE_PANEL_COLS`,
  `try_simd_ple_panel_base`, `has_simd_ple_panel_base`.
- `Fp<P>` for `P <= 251` overrides `PLE_PANEL_COLS = 256` (= `KC`)
  and registers the AVX2 panel-base kernel via
  `simd_ops::fp_try_ple_panel_base`.
- New unsafe AVX2 kernel
  `crates/gf2-kernels-simd/src/x86/fp_small_ple.rs` implements the
  row-major axpy-style Schur update with **fused scale + Schur** per
  pivot row, using SSOT `barrett_reduce_lane32` for reduction.
- Safe wrapper `crates/gf2-kernels-simd/src/fp_small_ple.rs` exposes
  `SmallPrimePlePanelFns` + `detect()`.
- `crates/gf2-core/src/lib.rs` adds `maybe_fp_small_ple()` OnceLock.

## Risks and limitations

- **Algorithmic ceiling.** The panelized base case retains the outer
  column-by-column pivot loop. The structural gap to fflas-ffpack's
  recursive PLUQ blocking is large for GF(251) (3.6× to close on
  n=256). Closing it requires a recursive panel × panel PLUQ
  reorganisation, not a kernel-level optimisation.
- **Out-of-scope: AVX-512.** Per `feedback_avx512_scope_to_7f809931`,
  AVX-512-based panel kernels are routed to epic `7f809931`. This
  closure deliberately stays within AVX2.
- **GF(127)/GF(241) reference absent.** No fflas-ffpack rows for
  these primes in the `dece4e73` aggregate CSV; cells are INFO-only.
