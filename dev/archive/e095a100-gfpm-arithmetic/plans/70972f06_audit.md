# 70972f06 Audit — Gf2mPoly_ / Gf2mPoly usage

Session 3 rework. Migration strategy chosen: **A — type alias** (`pub type Gf2mPoly_<V> = FieldPoly<Gf2mElement_<V>>`). The number of call-sites and tests outside the old `Gf2mPoly_` impl block is small, but the tests inside `gf2m/field.rs` (~ 100 occurrences) would require a total rewrite under Strategy B. Strategy A keeps the `Gf2mPoly_` / `Gf2mPoly` names usable so the internal tests and all downstream call-sites compile with at most cosmetic changes.

## Summary of ported methods

Ported to `FieldPoly<F: FiniteField>` as inherent impls / operators:
- `mul_karatsuba` (with `KARATSUBA_THRESHOLD = 32`), dispatched from the `Mul` operator.
- `div_rem(&self, &Self) -> (Self, Self)` — requires `F: FiniteField` only (uses `F::inv()`).
- `gcd(&Self, &Self) -> Self`.
- `eval(&self, &F) -> F`.
- `eval_batch(&self, &[F]) -> Vec<F>`.
- `from_roots(&[F]) -> Self`.
- `product(&[Self]) -> Self`.

Relocated onto `Gf2mElement_<V>` / `FieldPoly<Gf2mElement_<V>>` specialisation:
- `Gf2mElement_::minimal_polynomial(&self) -> FieldPoly<Gf2mElement_<V>>`.
- `FieldPoly<Gf2mElement_<V>>`: `from_bitvec`, `to_bitvec`, `to_bitvec_minimal`, `from_bitvec_reversed`, `to_bitvec_reversed`, `from_exponents`, `x(field)`.

Removed entirely (replaced by `FieldPoly` via alias):
- `Gf2mPoly_::new`, `zero`, `constant`, `degree`, `is_zero`, `coeff`, `normalize`, `monomial`, `from_roots`, `product`, `eval`, `eval_batch`, `div_rem`, `gcd`, `mul_schoolbook`, `mul_karatsuba`.
- `impl PartialEq/Eq/Add/Mul for Gf2mPoly_<V>`.
