## Traps — do not repeat these

**Carry forward** (link, don't copy): sessions 1–11 handoffs' Traps. All still in force.

**New session 12 traps:**

- **Shell `cd` state leaks across Bash calls** — When the lead uses `cd .claude/worktrees/agent-XXXX` to inspect a worker branch via the Bash tool, subsequent commands in later Bash calls still run from that worktree directory. A `git merge` issued thereafter lands on the worktree's branch, NOT on main. **Workaround:** always prefix critical commands with `cd /home/vkaskivuo/Projects/gf2 && ...` if there's any chance the shell state has drifted. The Bash tool description's "working directory persists between commands" is the relevant detail. Memory: [[shell-cwd-persistence]] (new — write this memory).

- **Merge conflict marker removal can eat lines outside the markers** — When using `Edit` to remove `<<<<<<< HEAD`, `=======`, or `>>>>>>>` lines from a conflict, the edit may inadvertently consume the line immediately adjacent (e.g., a closing `}` of a function definition that was the line right before `=======`). The conflict marker lines visually align with the start of code lines; an off-by-one in the Edit's `old_string` boundary can eat the wrong line. **Workaround:** after a conflict-marker edit, ALWAYS run `cargo check` before committing to catch syntax errors. Memory: [[merge-marker-edit-careful]] (new — write this memory).

- **Workers should use `random_fp_rank_deficient::<P>(n, n, rank, seed)`** — Manually duplicating rows to construct a rank-deficient matrix (e.g., copying row 0 into row 32 for a 64×64 GF(65521) test) creates rank n-1, not rank n/2 as intended. The single-row duplication does test singular-matrix handling but doesn't test the rank-n/2 regime the bench harness uses for "deficient". **Workaround:** include in dispatch prompts: "Use `random_fp_rank_deficient::<P>(n, n, rank, seed)` for rank-deficient test inputs; never manually duplicate rows."

- **6a7d4c8e + 9138d86c both touch `crates/gf2-core/src/field/matrix.rs` + `crates/gf2-core/src/field/inverse.rs`** — Sequential merges produced two non-trivial conflicts (one auto-merge in matrix.rs that worked, one content conflict in inverse.rs that needed manual resolution preserving both test additions).
