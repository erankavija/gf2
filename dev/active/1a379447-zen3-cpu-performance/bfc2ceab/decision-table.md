# Decision table: checked or unchecked kernel entry points

> **Diátaxis Type:** Reference

Generated by `survey/make-inventory.py`; the rows are those of [`inventory.md`](inventory.md), the instruction counts those of [`survey/instruction-counts.json`](survey/instruction-counts.json) under its `rule`. An instruction count is no timing: it states what the prototype of the check adds outside panic blocks, with each loop body counted once.

Option (a) puts a release-mode check in the safe entry point, in the form of the M4RM Gray-table builders. Option (b) makes the pointer an `unsafe fn` with the condition under Safety, so each caller holds an `unsafe` block with a `// SAFETY:` comment. `gf2-core`, `gf2-algebra` and `gf2-coding` deny `unsafe_code` (`core-denies-unsafe`, `algebra-denies-unsafe`, `coding-denies-unsafe`), so a production call site there cannot hold that block: for such an interface option (b) keeps a checked safe entry in the kernel crate, at the same or a coarser grain, and makes only the inner kernel `unsafe`.

## Sparse row kernels: one index bound per stored non-zero

Check (a): After one subtraction and one division per call, one comparison per non-zero of the row ahead of the kernel. Granularity: per element, once per call. The scan runs once per row call and leaves the kernel's loops as they are: the kernel reads each index once per 16 output columns and once per remaining column. A check that sits beside a whole matrix needs the row loop inside the kernel crate. On a hot path: yes: one scan per sparse row of every product.

## PLE panel base kernels: window shape and inverse-table index

On a hot path: per pivot column, outside the row and lane loops.
