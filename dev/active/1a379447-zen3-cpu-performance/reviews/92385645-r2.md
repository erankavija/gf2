# Review — M4RI matched-operation qualification (`92385645`), round 2

**Reviewed commit:** `ee818e9d`

**Verdict:** REWORK

## Blocking finding

The second provenance rework does not normalize GNU `MAKEFLAGS` or
`GNUMAKEFLAGS` before M4RI's configure/build/install sequence. GNU Make treats
variables inherited through either channel as command-line overrides. A hostile
`MAKEFLAGS='CC=clang ...'` can therefore make Clang compile the retained library
while the generated Makefile and the recorded provenance still identify the
pinned GCC executable.

The cache subsequently accepts the digest of that falsely attributed library.
The existing regression script covers ambient `CC`, `CPPFLAGS`, `LDFLAGS`,
`LIBS`, and `CONFIG_SITE`, but it does not exercise either make-level override
channel on a genuinely fresh cache.
