# Candidate profile provenance (jit:fcb04d66)

The [factor 2](../../bench_results/bc091474/profile-unroll2/profile-summary.md) and [factor 4](../../bench_results/bc091474/profile-unroll4/profile-summary.md) profile tables use these committed runtime records:

- **Factor 2:** [top-level invocation](../../bench_results/bc091474/profile-unroll2/invocations.log), [host and driver identity](../../bench_results/bc091474/profile-unroll2/host.txt), [repetition status and driver digest](../../bench_results/bc091474/profile-unroll2/repetitions.log), [case list](../../bench_results/bc091474/profile-unroll2/cases.txt), and [recorded-symbol cases](../../bench_results/bc091474/profile-unroll2/recorded-cases.txt). Each `rep-01` through `rep-09` directory has its own `invocations.log`; [rep-01](../../bench_results/bc091474/profile-unroll2/rep-01/invocations.log) and [rep-09](../../bench_results/bc091474/profile-unroll2/rep-09/invocations.log) show the sweep, exact `perf stat`/`perf record` commands, executable path, case, counter groups, and duration.
- **Factor 4:** [top-level invocation](../../bench_results/bc091474/profile-unroll4/invocations.log), [host and driver identity](../../bench_results/bc091474/profile-unroll4/host.txt), [repetition status and driver digest](../../bench_results/bc091474/profile-unroll4/repetitions.log), [case list](../../bench_results/bc091474/profile-unroll4/cases.txt), and [recorded-symbol cases](../../bench_results/bc091474/profile-unroll4/recorded-cases.txt). The corresponding [rep-01](../../bench_results/bc091474/profile-unroll4/rep-01/invocations.log) and [rep-09](../../bench_results/bc091474/profile-unroll4/rep-09/invocations.log) logs expose the same command fields; every intervening repetition also has a committed command log.

The `host.txt` records are runtime observations: they state the measured driver's SHA-256, experimental Rust cfg, Rust 1.95 and `perf` versions, CPU, and host state. The `repetitions.log` records bind every completed repetition to that driver digest. The top-level logs name the profile launcher; the per-repetition logs contain the exact child invocations. These files provide the command and runtime-version provenance behind the profile summaries without changing either receipt.

**Source-derived fixture identity:** [the frozen cell table](../2037941f-profile-and-optimize-mid-range-buffer-operations/survey/harness/src/cells.rs) declares addendum identity `2037941f-logical-buffer-v1`, the campaign seed, and ordinal-to-workload-seed expansion through canonical `SplitMix64`. [The profile driver](../2037941f-profile-and-optimize-mid-range-buffer-operations/survey/harness/src/bin/logical-profile.rs) takes each cell's seed and passes it to the [XOR and row fixture builders](../2037941f-profile-and-optimize-mid-range-buffer-operations/survey/harness/src/fixture.rs); that fixture source defines bank fill order, layout, and tail masking. The generator itself is [tuning-campaign-support's `SplitMix64`](../../tools/tuning-campaign-support/src/abtest.rs). The driver emits schema `logical-buffer-profile-case-v1`. These are source declarations and derivations, not values captured in `host.txt`.

The [profile launcher](../2037941f-profile-and-optimize-mid-range-buffer-operations/survey/run-logical-profile.sh) builds the named driver in release mode with the factor cfg, selects the candidate cases, and records the host, commands, and repetition status. The producing source files above have no diff from the `gf2` revisions recorded by either profile's host record to this task's anchor; the runtime driver digests in those records remain the executable identities.
