# Location-independent harness rules (jit:70a63a20)

## Rules

`HARNESS_RULES` in
`dev/active/1a379447-zen3-cpu-performance/3be770d5/survey/summarize-profile.py`
names `gf2.rs` and `pool.rs` by their suffix from the issue directory on,
`/3be770d5/survey/harness/src/`, which the chains built under
`dev/active/3be770d5/` and the sources under the epic directory share. Every
tracked file ending in either suffix is that harness source at one of the two
locations or a receipt's snapshot of it.

The comparator shim, reached through a relative include, has its own rule
(`SHIM_RULES`) in the update and batch executables' rules. The steady-state
executable's rules omit it: the committed `v4-r1-steady-profile` summary
records the shim's samples under `other:aff3ct_shim.cpp` and
`other:stl_vector.h`, because the shim rule of its generator names a path the
relative include does not end with. The self-test categorizes harness chains
at both locations under every executable's rules, and the shim chain under
each executable's rules.

## Steady-state series (REQ-02)

[reproduce-steady-summaries.py](reproduce-steady-summaries.py) copies each
committed series beside the summarizer's `preparation` directory to its own
repository path in a scratch repository, regenerates it there with the
working-tree summarizer from the committed `attribution-chains.json`, and
writes [comparison.tsv](comparison.tsv). Each case line compares
`total_samples` and the whole `categories` list (samples, share, Wilson bounds,
session range) with the committed `profile-summary.json`; every case reads
`categories identical`. The remaining lines list each byte difference:

| Difference | Run-time fact it records |
|---|---|
| `profile-summary.json` `/resolution/reused`; the `Address resolution` line of `profile.md` | Reuse of the committed chains: the pinned executable is absent |
| The `Generated by` line of `profile.md` | Generator path: the committed summaries name the summarizer at `dev/active/3be770d5/` |
| The bootstrap line of `profile.md` | Interpreter version of the bootstrap generator |

`attribution.tsv` and `attribution-chains.json` reproduce byte for byte.
Consecutive runs write identical `comparison.tsv` bytes.
