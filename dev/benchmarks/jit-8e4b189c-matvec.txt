- dense_matvec/512 has stride_words = 512 / 64 = 8, so with --all-features and AVX2 it enters BitMatrix::matvec_simd.
- dense_matvec/1024 has stride_words = 1024 / 64 = 16, so with --all-features and AVX2 it also enters BitMatrix::matvec_simd.
- The R1 SIMD path calls LogicalFns::and_popcnt_fn once per matrix row. This avoids the rejected R0 scratch-buffer route (xor_fn + and_fn + popcnt_fn) while keeping unsafe SIMD isolated in gf2-kernels-simd.
- Scalar ILP fallback remains only for rows below 8 words or for hosts without a SIMD backend; it is not the path used by the 512/1024 A1 design sizes on this host.

- R1 lowers the dispatch threshold to 8 words because the fused SIMD AND+popcount route is above the 1.5x A1 bar at the first A1 design size (512 columns / 8 words) and remains above the bar at 1024 columns / 16 words.
- The scalar fallback can still be faster in absolute terms for some sizes, but the issue contract requires the 512/1024 speedup to come from SIMD routing; R1 intentionally routes those design sizes through SIMD and documents the measured SIMD result.
