# gf2 formal verification (Lean4)

Machine-checked correctness proofs for `gf2-core` finite-field arithmetic. Lean4 function bodies are auto-generated from the live Rust source via [Charon](https://github.com/AeneasVerif/charon) (Rust → LLBC) and [Aeneas](https://github.com/AeneasVerif/aeneas) (LLBC → Lean); the hand-written proofs in `Gf2Core/Proofs/` then discharge specifications on those bodies.

## Scope

Currently extracted and verified:

- **`gfp/`** — `Fp<const P: u64>` prime field with Montgomery multiplication, including the specialized Mersenne/Proth backends.
- **`gfpn/`** — `QuadraticExt<C>` and `CubicExt<C>` tower extensions over the `ExtConfig` trait.
- **`gf2m/`** — bit-level GF(2^m) arithmetic: addition, raw multiplication, inversion.

All prime-field proofs apply to `ValidPrime P` (odd prime P ≤ 2^63). The restriction P ≠ 2 is inherent to Montgomery arithmetic: R = 2^64 requires gcd(R, P) = 1.

## Layout

Generated (do not edit by hand):

| File | Contents |
|---|---|
| `Gf2Core/Types.lean` | Type definitions (`Fp<P>`, `MontConsts<P>`, trait structs, tower-extension configs) |
| `Gf2Core/Funs.lean` | Function bodies translated from Rust |
| `Gf2Core/FunsExternal_Template.lean` | Axiom template generated by Aeneas for std-library ops |

Committed alongside the generated files:

| File | Contents |
|---|---|
| `Gf2Core/FunsExternal.lean` | Concrete defs (replacing four external axioms, e.g. `wrapping_neg`, `overflowing_sub`, `U128 add`) |

Hand-written proofs under `Gf2Core/Proofs/`:

| File | Contents |
|---|---|
| `Defs.lean` | `ValidPrime P` predicate, `FpVal P` wrapper type |
| `Progress.lean`, `ExtProgress.lean`, `Gf2mProgress.lean` | Result-elimination lemmas (`progress`-compatible) for every extracted function |
| `ModArith.lean` | Pure modular arithmetic: roundtrip, add / mul / neg specs |
| `MontgomeryRoundtrip.lean` | Headline theorems on the Rust source: `redc_value_spec`, `montgomery_roundtrip`, `fp_add_correct`, `fp_mul_correct`, `p_inv_value_spec` |
| `FpField.lean` | `CommRing` / `Field` instance for `FpVal P` via equivalence with `ZMod P.val` |
| `ExtDefs.lean`, `ExtAlgebra.lean`, `QuadraticExtField.lean`, `CubicExtField.lean` | Tower extensions — ring and field structure |
| `Gf2mDefs.lean`, `Gf2mAddition.lean`, `Gf2mMulRaw.lean`, `Gf2mInverse.lean` | GF(2^m) correctness (addition = XOR, multiplication spec, inverse via extended Euclidean) |

Post-processing quirks are documented in [`WORKAROUNDS.md`](WORKAROUNDS.md).

## Build

Minimal — just rebuild committed Lean sources. Needs [`elan`](https://github.com/leanprover/elan):

```bash
cd proofs && lake build
```

Full pipeline — regenerate from Rust, then build. Needs patched Charon + Aeneas + elan:

```bash
./scripts/verify-lean.sh
```

Commit regenerated files when Rust source under `gfp/`, `gfpn/`, or `gf2m/` changes:

```bash
./scripts/verify-lean.sh && git add proofs/Gf2Core/
```

## Prerequisites for regeneration

1. **Lean4** via elan:

   ```bash
   curl -sSf https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh | sh
   ```

2. **Charon** — our pipeline uses a patched local build at `/data/aeneas-build/charon/` (upstream base plus three HRTB / associated-type fixes). Requires nightly `nightly-2026-02-07`:

   ```bash
   rustup toolchain install nightly-2026-02-07
   rustup component add rustc-dev llvm-tools-preview rust-src --toolchain nightly-2026-02-07
   ```

3. **Aeneas** — OCaml 5 via opam:

   ```bash
   opam init && eval $(opam env)
   opam install ppx_deriving visitors easy_logging zarith yojson core_unix \
       odoc ocamlgraph menhir unionFind zarith progress domainslib dune
   git clone --depth 1 https://github.com/AeneasVerif/aeneas.git /tmp/aeneas
   cd /tmp/aeneas && make setup-charon && make build-dev
   cp /tmp/aeneas/bin/aeneas ~/.cargo/bin/
   ```

See `dev/lean4-verification-pipeline.md` for the full rebuild procedure and the Charon patches.

All committed proofs check with **zero `sorry`s and zero axioms** across the prime field, tower extensions, and GF(2^m). This includes the Newton-iteration `p_inv_value_spec` and the full `montgomery_roundtrip` chain — both previously tracked gaps are closed.
