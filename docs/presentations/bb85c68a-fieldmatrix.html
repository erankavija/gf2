Architecture: one API, many fields

Design choice

  • BitMatrix remains the specialized GF(2) path.
  • FieldMatrix<F> covers arbitrary FiniteField values.
  • MatrixLike<Elem> gives shared shape/get/set behavior without forcing one representation.
  • High-level API is ergonomic; hot kernels are imperative and allocation-budgeted.

Algorithm spine

PLE(A) = (P, L, E, r)

P · L · E = A

From this one factorization: rank, echelon, RREF, LU, nullspace, solve, inverse, determinant.

This follows the Dumas-Pernet plan: reduce factorizations to gemm and triangular solves.

Example: solve a linear system over GF(65521)


use gf2_core::field::matrix::FieldMatrix;
use gf2_core::field::FieldVec;
use gf2_core::gfp::Fp;

type F = Fp<65521>;

let mut a = FieldMatrix::<F>::zeros(3, 3);
a.set(0, 0, F::new(2));  a.set(0, 1, F::new(1));  a.set(0, 2, F::new(0));
a.set(1, 0, F::new(1));  a.set(1, 1, F::new(3));  a.set(1, 2, F::new(1));
a.set(2, 0, F::new(0));  a.set(2, 1, F::new(1));  a.set(2, 2, F::new(4));

let b: FieldVec<F> = vec![F::new(7), F::new(11), F::new(13)].into();
let x = a.solve(&b).expect("matrix is nonsingular");

// Verify A x = b using the same finite-field arithmetic.
assert_eq!(a.matvec(&x), b);

Use this pattern for syndrome solving, interpolation systems, cryptographic linear constraints, and rank-profile experiments.

Example: rank profile and nullspace


use gf2_core::field::matrix::FieldMatrix;
use gf2_core::gfp::Fp;

type F = Fp<7>;

let mut h = FieldMatrix::<F>::zeros(2, 4);
h.set(0, 0, F::new(1));
h.set(0, 1, F::new(2));
h.set(0, 2, F::new(3));
h.set(0, 3, F::new(4));

// Second row is 2x the first row.
for c in 0..4 {
    h.set(1, c, F::new(2) * h.get(0, c));
}

assert_eq!(h.rank(), 1);
let basis = h.nullspace();
assert_eq!(basis.len(), 3);

Expression templates: write math, get one kernel

Canonical expressions fuse instead of materializing every intermediate.


use gf2_core::field::expr::Evaluate;
use gf2_core::field::matrix::FieldMatrix;
use gf2_core::gfp::Fp;

type F = Fp<2_147_483_647>; // Mersenne-31

let a = FieldMatrix::<F>::random_seeded(1024, 1024, 0xA11CE);
let b = FieldMatrix::<F>::random_seeded(1024, 1024, 0xB0B);
let c = FieldMatrix::<F>::random_seeded(1024, 1024, 0xC0DE);
let beta = F::new(5);

// A·B + beta·C: evaluated as one fused matrix kernel.
let out: FieldMatrix<F> = ((&a * &b) + (beta * &c)).into();

// A^T·B is also a first-class proxy.
let gram: FieldMatrix<F> = (a.t() * &b).into();

The shipped expression layer includes trace counters and tests that the canonical forms collapse to one kernel call.

Example: characteristic and minimal polynomial


use gf2_core::field::matrix::FieldMatrix;
use gf2_core::gfp::Fp;

type F = Fp<251>;

let a = FieldMatrix::<F>::random_seeded(128, 128, 0xC0FFEE);

let chi = a.charpoly();  // deterministic cubic baseline
let mu  = a.minpoly();   // Krylov + LCM strategy

// Cayley-Hamilton style experiments now stay in Rust:
assert_eq!(chi.degree(), 128);
assert!(mu.degree() <= 128);

Example: sparse constraints and graph matrices


use gf2_core::field::sparse_matrix::SparseFieldMatrix;
use gf2_core::field::FieldVec;
use gf2_core::gfp::Fp;

type F = Fp<65521>;

// COO-style construction: one entry per nonzero.
let entries = vec![
    (0, 0, F::new(1)), (0, 3, F::new(4)),
    (1, 1, F::new(2)), (1, 4, F::new(5)),
    (2, 2, F::new(3)), (2, 5, F::new(6)),
];
let a = SparseFieldMatrix::from_entries(3, 6, entries);

let x: FieldVec<F> = (0..6).map(F::new).collect::<Vec<_>>().into();
let y = a.matvec(&x);

assert_eq!(y.len(), 3);

This is the entry point for LDPC-style parity checks, Tanner-graph transforms, sparse interpolation systems, and expander experiments over non-binary fields.

Three research workflows now enabled

1. Non-binary code design

Build sparse parity checks over Fp or GF(2^m), compute rank/nullspace, and measure encoder/decoder structure.

2. Algebraic algorithms

Prototype block Wiedemann, Krylov minpoly, Keller-Gehrig charpoly, PLE variants, and rank-profile algorithms.

3. Cryptographic systems

Experiment with finite-field constraint systems, invertibility distributions, matrix pencils, and tower-field transforms.

The important shift: researchers can use one strongly typed Rust surface instead of hopping between bit matrices, handwritten GF(p) code, Sage scripts, and C++ reference harnesses.

Why this matters even before SOTA parity

CAS-style ergonomics

  • Armadillo-shaped constructors and free functions.
  • Operator expressions for matrix products and sums.
  • Typed fields, including runtime-context fields.
  • All inside the Rust test/bench ecosystem.

Systems-style control

  • No unsafe code in gf2-core.
  • Reproducible benchmark harness and pinned external references.
  • Room to add SIMD/GPU kernels behind the same API.
  • Direct integration with coding-theory simulations.

The baseline says: ready for research use; not yet done for SOTA performance.

Correctness posture

  • Rank deficient PLE, inverse, rank, nullspace, and benchmark regimes include explicitly deficient inputs.
  • Boundary cases Empty runtime-context Gf2mElement PLE was fixed during epic closure and regression-tested.
  • No unsafe High-level matrix code remains under #![deny(unsafe_code)]; unsafe is isolated in kernel crates.
  • Gates Every child story and the epic passed cargo-ci, code-review, and doc-review.

The review loop was expensive, but it hardened the exact boundary conditions research code tends to hit first.
